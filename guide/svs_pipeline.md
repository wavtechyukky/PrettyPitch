# SVS 全体の構成

楽譜を読み込んで波形を返すまでに、3 つの学習済みモデルと、いくつかの決まった手順が順に動きます。

![SVS 全体構成](fig/svs_pipeline.svg)

## 1. 楽譜のロード

`svs/score_io.py` が MusicXML と UST を同じ中間形式に正規化します。歌詞はモーラ表（`dict/<lang>.yaml` の `mora:`）で音素列に変わり、0.5 秒以上の休符でフレーズに切られます。

フレーズが合成の単位です。フレーズごとに合成して、最後に楽譜上の時刻へ並べ直します。

### MusicXML のどこまでを読むか

楽譜ソフトが書き出したファイルをそのまま渡せます。`.mxl`（MuseScore の既定の保存形式。中身は zip）も開きます。伴奏つきの譜面では**歌詞のあるパートを 1 つだけ**歌います（`--part` で id か part-name を指定して変えられます）。タイは 1 つのノートに畳みます。畳まないと伸ばしの途中で音素が切り直され、余分なノート境界がピッチ補正にも入ります。

読めないものもあります。**同じパート内の複数声部と `<backup>`／`<forward>`、繰り返し記号、途中のテンポ変更、途中で変わる `divisions`** は未対応です。黙って違う音を出さないよう、見つかったら読み込み時に警告を出します。繰り返しのある譜面は、展開してから渡してください。

### 歌詞のかわりに音素を書く

歌詞は `dict/<lang>.yaml` の `mora:` が指すモーラ表で音素に変わります。日本語なら「か」と書けば `k a` になります。

**歌詞欄に音素を直接書くこともできます。** 空白で割って全部が音素表にあるとき、そのまま音素列として扱います。

| 歌詞欄 | 音素 |
|---|---|
| `か` | `k a`（モーラ表を引く） |
| `ky o` | `ky o`（音素として直接） |

### 韓国語・中国語・英語の歌詞（G2P）

言語パックに `g2p:` があると、モーラ表の代わりに規則の G2P で歌詞を音素にします。休符を挟まずに続く音符の並びごとにかけるので、前後の音節で読みが変わる所も扱えます。

| 言語パック | G2P | 歌詞の例 |
|---|---|---|
| `ko` | `svs/g2p_ko.py`（ハングル → Team CODA の音素。連音・鼻音化・濃音化・激音化・流音化など） | `사랑` → `s a r a NG` |
| `zh_acv` / `zh_opencpop` | `svs/g2p_zh.py`（漢字 → 拼音（熟語で多音字を読み分ける）→ 音素。小文字の拼音もそのまま書ける） | `看` → `k a N`（ACV）・`k an`（Opencpop） |
| `en_full` | `svs/g2p_en.py`（CMUdict の発音辞書。強勢の無い AH0 は `ax`） | `hello` → `hh ax l ow` |

英語では、`[hh eh l ow]` や `word[...]` のように角かっこで囲むと、音素として読みます。辞書に無い語は音素で書いてください。

**伸ばしと音節の記号**: 「-」「ー」と歌詞の無い音符は、前の音符の母音を伸ばし、終声（韻尾・終わりの子音）は伸ばしの最後の音符へ移します（「밤」「-」→ `b a | a M`）。英語では複数の音節の単語を 1 つの音符に書き、続く「+」の音符へ音節を配ります（`again` `+` → `ax | g eh n`）。`+~`・`+*` は伸ばし、`+3` は単語の 3 番目の音素からです。`++` と余った音節の扱いは `score_to_phrases` の `lyric_style`（`sequential` か `count`）で選べます。日中韓は 1 音符に 1 音節なので「+」は伸ばしと同じです。

**ただし同梱ウェイトでは日本語以外を歌えません。** 楽譜は読めますが、F0・子音長・音響のいずれも日本語 3 話者で学習したもので、ほかの言語の音素が語彙にありません（`phonemes not in the model vocab` で止まります）。ほかの言語で歌わせるには、その言語のデータで自分で学習することになります（設定の例は `configs/ko_coda.yaml`・`configs/zh_acv.yaml`・`configs/zh_opencpop.yaml`・`configs/en_aidol.yaml`）。

参考までに、御丹宮くるみ歌声データベース同梱の MusicXML 56 本（すべて MuseScore 3.4.2 出力）は、警告なしで全部読めます。タイは 6931 ノート中 348 に付いていました。

## 2. 持続長の決定

子音長モデルが音素ごとの子音長を予測し、後処理が母音との取り分を決めます。詳しくは [duration_model.md](duration_model.md) を読んでください。ここで決まるのはフレーム数で、以降のモデルはすべてこのフレーム列の上で動きます。

## 3. F0 生成

F0 モデルが baseline・plain・vibrato・v/uv を出し、合成して F0 にします。図とコードで呼び名が違う層が 1 つあります。図の expression が抑揚の層で、コードと設定キーでは plain です。構成は [f0_model.md](f0_model.md)、学習に使う代表値は [representative_pitch.md](representative_pitch.md)、plain と vibrato の分け方は [vibrato_separation.md](vibrato_separation.md) にあります。

## 4. ピッチ補正

2 段の決まった補正を plain に当てます（[pitch_correction.md](pitch_correction.md)）。狙う値は楽譜のノート音高です。生成された F0 の近く的な音高を推定し、その差を埋めます。

## 5. 音響モデルとボコーダ

ここから先は LeapSinger の音響モデルと NHVSing のボコーダです。音響モデルが音素列・フレーム長・F0 から 128 次元の log-mel を作り、ボコーダが mel と F0 と有声/無声から波形を合成します。

音響モデルは v/uv を条件に取りませんが、ボコーダには渡しています。無声フレームで倍音の励起を落とし、ノイズ成分だけを残すためです。

## 6. 音量を整える

**ボコーダに渡す前に mel を 2 つ調整します。** ここが唯一 mel に手を入れる場所です。

**ラウドネス合わせ。** 有声フレームの mel の大きさを目標値へ、定数を足して揃えます。ボコーダは学習データを有声区間の実効値 0.111 に正規化したうえで学習しているので、その音量で駆動するのがいちばん得意です。ここを合わせずに波形側で音量を上げると、信号と一緒にボコーダのノイズも持ち上がります。実測で、合わせない場合は波形を最大 2.3 倍する必要がありました。

**フレームリミッタ。** それでも大きすぎるフレームがあれば、そのフレームだけ全体を下げます。同梱のボコーダは出力の直前に −1 から 1 で切る処理を持っているので、音量の大きな mel を渡すとそこで波形が潰れます。実際に働くのは全フレームの 0.1% 未満で、普段は保険として置いてあります。

**波形には手を入れません。** 音量は mel の段で決まっているので、出てきた波形をさらに掛け直すことはしません。実測で、曲と話者をまたいだ振れ幅は 1.55 dB、ピークは 0.32〜0.68 に収まります。旧来のようにピークを 0.95 へ揃えたい場合だけ `--normalize peak` を使います。

## 機械学習ベースの部分とルールベースの部分について

| 学習している | 決まった手順 | そもそも要らない |
|---|---|---|
| 子音長・F0・mel | フレーズの配置、子音長の下限と圧縮、ピッチ補正、音量の調整 | ノートの開始時刻、ノートの音高、参照楽譜 |

楽譜を読むのは推論のときだけです。学習には歌声の wav と音素ラベルしか要りません。音高の教師は歌声の F0 そのものから作ります。これが「楽譜フリー」の意味です。

## 話者とスタイル

話者 id は子音長モデル・F0 モデル・音響モデルの 3 つすべてに渡ります。同じ楽譜でも話者ごとに子音の長さが変わるので、出力の全体長もわずかに変わります。

音域は話者ごとに違うので、楽譜が合わないときは `--transpose` で半音単位に寄せてください。

## 合成

```python
from svs.render import render_score
wav, sr = render_score("examples/kirakiraboshi.musicxml", spk_id=2)
```

モデルを 1 度だけ読み込んで何度も合成するときは `load_models()` で `SvsContext` を作り、`render_score(..., ctx=ctx)` に渡します。このとき `spk_id` や `lang` は**黙って無視されます**。話者は `load_models(spk_id=...)` の時点で決まるので、話者を変えるなら `SvsContext` を作り直してください。フレーズ単位で途中経過が欲しいときは `render_phrase()` が持続長・F0・mel・波形をすべて返します。
